# Vera Anchor Verifier SDK

**Status: Phase 0 (architecture and contract audit). Not released. No verification implementation shipped yet.**

Independent, read-only, local-first verification of digital evidence. The planned SDK will
support offline cryptographic recomputation, evidence-profile verification, independent
source-aware triangulation, portable findings, and later policy evaluation. It will not
require producer-side Hash Factory SDKs or Vera Anchor credentials for local use.

## Repository setup

Requirements: Git; Node.js 24 LTS recommended (22 LTS supported); npm; access to npm registry.

```sh
npm install
npm run pin:actions
npm run format
npm run check
npm run typecheck
npm test
npm run build
npm pack --dry-run
```

Commit `package-lock.json` generated by `npm install` before the first push. CI uses `npm ci`.
Review the `pin:actions` diff: it resolves the approved GitHub action release tags to full
immutable commit IDs via GitHub's public API, and must be run before enabling CI on external PRs.

For local debugging of format rules: `npm run format`. This intentionally changes files.

## Runtime and package surface

- Intended npm identity: `@vera-anchor/verifier` **pending verification of ownership of the npm scope**.
- GitHub home: `https://github.com/VeraAnchor/vera-anchor-verifier` (create the repository before pushing).
- ESM only; Node.js 22/24 targeted initially; browser-compatible pure kernel is an architectural goal.
- Strict TypeScript, no runtime dependencies, separate pure kernel and future optional resolvers.
- Publishing is disabled (`private: true`) until the name, API, license, and audit are approved.

## Trust boundaries

Evidence is not self-authenticating. Verification intent must be independently supplied,
observation provenance and dependency must be represented, and no network request is allowed
in offline mode. Mirror-node observations are not authenticated consensus proofs. Core-generated
Merkle roots and tenant-side Hash Factory anchor requests are different evidence products.
An original HCS anchor is not a public publication receipt. Cryptographic integrity does not
prove the truth or quality of the underlying content.
